更新日期：2026-10-27
状态：P0、P1 与 P2 的本地实现已完成。GitHub 推送、远程 CI 与 Sites 发布分别记录，不等同于本地检查通过。

## 下次从哪里开始

先检查 Git 状态与实际代码。P0、P1、P2 已实现；初始化、发布检查与部署支持见 `docs/setup-p2.md`、`docs/deployment-p2.md`，最新验证见 `docs/verification-p2.md`。用户已授权完成后推送 GitHub 并发布 Sites 私有静态预览；跟进时先核对远程提交/CI与本机忽略的 `deploy/sites-preview.json`，复用同一 Site。后续功能需按新需求评估，不默认扩展聊天、账号或拖拽编辑器。

每完成一项，更新本文的复选框、实际改动和验证结果。遇到需求变化，保留决定及理由，避免后续开发重复推翻。

## 产品定位

目标用户：开发者和技术从业者，首批覆盖前端、后端、全栈及 AI 应用开发者。

双重定位：

- 对站点访客：一个能快速理解作者能力、检查作品依据并联系作者的双语个人作品集。
- 对模板使用者：一个能替换内容、选择外观、调整模块并自行部署的开源基础。

特色原则：每项能力都能找到作品，每项作品都能找到依据。用同一套经过授权的公开内容贯通简历、案例、贡献记录、搜索和资料助手。

首版暂不扩展到所有行业，也不建设通用建站平台。

## P0 开始前的基线与缺口

已有：Next.js、TypeScript、Tailwind、MDX；中英文页面；配置化基础资料；项目案例；文章搜索；贡献记录；简历打印；公开资料问答；测试与 CI 配置。

以下是实施前的审视记录，已修复项以 P0 复选框和验证记录为准：

- 首页和问答使用 `projects[0]`，没有健壮的空列表处理与精选项选择。
- 站点品牌、页脚、元信息、部分链接和介绍文案写在组件中。
- 开源页、README 等仍有“没有远程仓库”的旧描述；项目实际已上传至 https://github.com/Singmin/ai-portfolio-kit 。模板示例状态与当前项目状态需要区分。
- 首页结构固定，缺少模块开关、排序、展示数量与版式配置。
- 已有 CSS 变量，但缺少完整主题预设和统一的外观配置入口。
- 文章依赖手动导入和双语注册；新增语言、只使用一种语言都不够方便。
- 问答是独立维护的少量资料，与页面内容可能发生漂移；贡献摘录也没有完整联动贡献配置。
- 项目模型缺少封面、个人角色、团队背景、时间和证据链接等信息。
- 个人身份和经历仍为明确标注的示例；不得据此声称已有真实个人履历。
- 问答限流基于单机持久磁盘，不适合直接当作多机/serverless 的共享限流。

基线中的测试记录见 `docs/verification.md`，属于历史验证。开发时根据变更重新判断需要运行的检查，不将历史结果当成新版本已通过的证据。

## P0：先让内容和结构真正可替换

### P0-01 消除固定内容和首项依赖

- [x] 盘点页眉、页脚、元信息、站点介绍、默认语言、固定 slug 和链接，建立站点设置入口。
- [x] 区分模板自身的名称/仓库信息与个人站点的姓名/品牌/链接。
- [x] 移除首页和问答对 `projects[0]` 的必然依赖；采用明确的精选项选择和缺失回退。
- [x] 修正当前仓库状态的过期说明；历史验证文档保留时间语境。
- [x] 用第二套明确标注的示例资料验证替换过程，不把示例经历包装为真实事实。

验收：不修改页面组件，即可替换姓名、品牌、公开联系信息、项目及站点地址；空项目列表不报错；页面和资料助手没有旧项目标题、旧 slug 或失效引用残留。模板署名等保留项应有明确设计，而不是散落的固定文案。

### P0-02 模块开关、顺序和精选项配置

- [x] 设计有限的模块集合：个人介绍、精选项目、经历、文章、贡献、联系、资料助手。
- [x] 支持首页模块启用/禁用、排序、展示数量和精选项目选择。
- [x] 区分“隐藏首页模块”和“停用整个页面”；定义导航、页面访问、索引和直接链接的对应行为。
- [x] 内容为空时合理隐藏模块和相关导航，避免公开站点充满空记录提示。
- [x] 保留显式示例/预览模式，让模板使用者理解尚未填写的内容。

验收：只改配置，就能把文章移到项目之前、隐藏贡献、关闭资料助手并调整精选作品；禁用页面不会在导航、站点地图或资料助手中留下入口；未启用 AI 时无需 Key 即可浏览站点。

### P0-03 完善项目案例内容模型

- [x] 支持封面/截图及替代文本、时间、个人角色、个人贡献范围、团队背景、项目状态。
- [x] 保留问题、关键决策、实现结果，允许展示有依据的指标及其说明。
- [x] 支持多项证据：源码、演示、公开文章、PR、文档等；缺失时不生成假链接。
- [x] 将首页预览从固定的 Kit 页面截图扩展为使用者自己的项目媒体。
- [x] 为没有图片、没有演示、多人参与及多个项目设计合理展示。

验收：读者能看清项目是什么、作者具体做了什么、结果如何、在哪里核验；新增普通项目只需维护内容，不必改组件；未提供指标、截图或演示也可正常展示。

## P1：提升 DIY 和长期维护能力

### P1-01 三套完整视觉预设

- [x] 编辑式：大字、留白、项目叙事，延续当前方向。
- [x] 工程式：突出技术决策、实现细节和公开贡献。
- [x] 履历式：信息紧凑，方便招聘者阅读和打印。
- [x] 共用内容模型，提供配色、字体组合、密度、媒体比例和动态效果配置。
- [x] 整理全局样式与覆盖关系，避免新增主题不断叠加临时覆盖。

验收：同一份资料可切换三种明显不同的排版；主题差异包含布局和信息密度；三套均覆盖中英文、手机、键盘操作和减少动态效果模式。

### P1-02 简化内容维护与语言配置

- [x] 统一文章元数据和可信本地 MDX 的登记方式，减少重复维护。
- [x] 允许仅启用中文或英文，并定义默认语言与缺失翻译回退策略。
- [x] 导航、语言切换、元信息和站点地图共同使用有效内容清单。
- [x] 构建时校验 slug、引用、链接格式、媒体和翻译完整性，给出具体字段提示。
- [x] 明确草稿、示例、已发布内容的边界。

验收：新增文章无需在页面、站点地图和索引中分别补链接；只启用一种语言可正常构建；缺失翻译不会生成失效链接；草稿不会公开或进入 AI 索引。

实际边界：文章采用每篇一份 JSON 和按 slug/语言命名的可信 MDX；P1-03 起开发服务器自动同步登记和正文变化，`content:sync` 仍可手动执行。缺失翻译可隐藏或跳转到默认语言原文，静态链接/本地媒体校验范围见 `docs/content-p1.md`。共享个人资料、项目和品牌仍沿用 P0 的中英文对象类型；公开发布也不自动授予 AI 索引权限。

### P1-03 让资料助手服务真实访客任务

- [x] 产品文案准确说明当前“检索与来源筛选”的能力，不承诺通用聊天或自由推断个人经历。
- [x] 让公开内容成为页面、搜索和问答的共同基础，消除重复摘录的漂移。
- [x] 分别配置公开发布与 AI 索引授权；只有明确允许进入 AI 的已发布内容才能发送给模型。
- [x] 从授权内容生成有稳定 ID、有效页面链接及更新机制的证据条目。
- [x] 根据真实内容提供能力、个人职责、公开贡献和联系方式等建议问题。
- [x] 保留未知回答、原文引用、输出校验、超时、预算和无 Key 降级。

验收：修改授权内容后，页面与问答来源同步；删除/禁用内容后，不再被引用；未授权内容、草稿、私有文件和环境变量始终不进入索引；问答不编造职责、指标或贡献。

实际边界：项目、贡献和真实 profile 需显式 `aiIndex: true`，文章还需顶层静态 `PublicExcerpt` 标记；默认拒绝索引。移除手工复制文章摘录，来源由实际字段/正文生成，含稳定 ID、正文锚点与内容修订标识。开发自动同步已验证；生产变更需重建并重启/部署。保留关键词检索和原文输出，未增加通用聊天、私有文件扫描或模型训练；已索引字段及未覆盖内容见 `docs/evidence-p1.md`。

## P2：让别人能独立使用和发布

- [x] 提供初始化流程：填写资料、选择语言、主题和模块，生成配置并预览。
- [x] 增加发布检查：示例残留、联系方式、失效内部引用、缺失翻译、媒体和 SEO 设置。
- [x] 提供清楚标注的完整示例内容，演示不同资料量和主题，避免虚构真实客户与成果。
- [x] 完善创建副本、定制、升级、部署和排错文档；检查 GitHub 模板入口与版本发行方式。
- [x] 明确支持的部署路径；若支持多机/serverless 付费 AI，先接入并测试共享原子限流。
- [x] AI、主题和模块配置保持扩展边界，避免每添加一种选择都修改全站组件。

验收：新用户能按文档独立创建自己的站点；未接入 AI 也可完成发布；部署方案与限流存储实际一致；配置错误能定位到字段。

实际边界：本地 CLI 向导生成草稿，隔离预览，验证后原子应用并备份；版本化公开 JSON 覆盖现有配置。只读发布检查区分真实个人站点与明确标注的模板预览。三套完整示例覆盖语言、主题与内容量。支持单机 Node 及静态托管；静态版在浏览器检索、没有 API/付费 AI，多机/serverless 付费 AI 仍不支持。已开启 GitHub template 入口，正式 tag/release 流程已文档化，本次不自动创建稳定发行版。

## 暂不优先

- 拖拽编辑器、账号体系、多租户、付费系统、完整 CMS 后台。
- 无明确需求的多模型切换、向量数据库和通用聊天能力。
- 大量只有颜色变化的主题，以及面向所有行业的模板集合。
- 自动读取私人简历或其他仓库、未经授权自动发布、自动把所有公开资料发送给模型。

这些可以在真实使用需求明确后重新评估，不属于首批开发默认范围。

## 开发约束与检查

- 维护独立仓库，不复制私有 bagCollection 配置、数据或历史。
- 不伪造个人经历、指标、社区贡献或第三方评价。真实个性化资料与模板示例分开处理。
- 重构配置时给出现有配置的迁移说明；先确定内容模型和模块行为，再开发主题。
- 添加与变化相关的有效检查：空列表、单项目、多项目、模块禁用、单语言、缺失翻译、无图片、无 AI Key、未授权索引。
- 根据变更运行 lint、typecheck、单元/API 测试和 build；涉及页面行为时运行浏览器测试，涉及视觉时检查桌面和手机截图。
- 记录本地验证、远程 CI 和线上部署的不同状态，不混为“完成”。
- 本路线是开发依据，不代表用户已要求立即执行全部事项，也不等同于自动发布/推送授权；按后续明确的开发范围推进。
