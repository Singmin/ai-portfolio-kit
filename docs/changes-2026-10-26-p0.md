# 最近一次代码改动说明：P0 配置化改造

整理日期：2026-10-26。

本说明中的“最近一次”指当前工作区相对提交 `056583c`（`feat: build bilingual AI Portfolio Kit with evidence-based Q&A`）的未提交改动。当前分支为 `main`；Git 历史仍只有该初始提交，因此本轮改造尚未形成独立提交。内容依据当前代码、Git diff、路线文档及已有验证记录整理，无法仅凭 Git 精确还原每个未提交文件的修改先后。

## 这次主要解决了什么

把原来偏固定展示的作品集，改成可通过配置替换品牌、组合首页模块、控制页面访问和补充项目案例的模板。原有中英文页面及视觉方向继续保留，资料助手的来源也会跟随项目内容和页面开关变化。

## 1. 新增统一站点配置

- 新增 `src/config/site.ts`，集中管理站点品牌、默认语言、模板仓库、页脚、页面开关、导航顺序及首页模块。
- 区分个人站点品牌与模板署名，避免修改个人资料时仍到处残留模板名称。
- 页眉、页脚、页面元信息和根路径跳转接入配置。
- 新增 `src/lib/configuration.ts` 与 `src/lib/portfolio.ts`，组合并校验公开内容；检查重复 slug、重复模块、重复导航、失效精选项目引用及链接等配置问题。

实际效果：替换站点身份和结构时，主要维护配置文件，不必逐页改组件。

## 2. 首页支持模块组合与精选项目

- 新增 `src/components/home-view.tsx`，把首页内容拆成可配置模块：项目、文章、经历、贡献、关于、联系和资料助手；身份主视觉始终显示。
- 支持模块启用/禁用、排列顺序、列表数量及精选项目 slug；列表默认展示 3 项。
- 移除首页对首个项目的固定依赖，支持零个、单个及多个项目。
- 项目、文章、贡献等内容为空时，隐藏对应首页模块和导航；启用的空列表页仍可直接访问并显示空状态。
- 主视觉按钮按“可用项目页 → 简历页 → 公开联系方式”选择目标；没有可用目标时省略按钮。

实际效果：只改配置即可把文章放到项目之前、隐藏某个首页区块或调整精选作品，不需要改首页布局代码。

## 3. 页面开关贯通访问、导航和引用

- 新增 `src/lib/page-access.ts`，在页面入口检查启用状态。
- 简历、项目、文章、贡献和问答页面均接入开关；关闭项目或文章页时，对应详情页也返回 404。
- 新增 `src/lib/sitemap-entries.ts`，统一生成有效页面的站点地图条目；示例身份或缺少站点地址时不生成公开条目。
- 关闭页面后，同步移除对应导航、首页入口、站点地图条目和问答来源。
- 关闭问答时，`POST /api/ask` 在读取请求内容、消耗配额和调用模型之前返回 404。

需要区分：隐藏首页模块只影响首页展示；停用页面才会阻止直接访问并移除相关引用。

## 4. 项目案例支持更完整的资料

- 扩展 `src/config/projects.ts`，增加可选的时间、个人角色、团队背景、贡献范围、封面、截图、指标及多项证据。
- 新增 `src/components/project-views.tsx` 和 `src/components/project-media.tsx`，统一项目列表、详情和媒体展示。
- 证据支持源码、演示、文章、PR 和文档；保留原有 `repository`、`demo` 字段，合并展示并按 URL 去重。
- 缺少图片、职责、指标或演示时省略对应区域，不生成虚构内容或占位链接。
- 图片使用本地公开资源，并校验媒体路径及中英文替代文本。
- Kit 的预览图片归入具体项目配置；替换项目时不会固定带入 Kit 的截图。刷新了 `public/previews/` 下的文章、贡献、项目和简历四张预览图。

实际效果：读者可以在案例中查看作者实际负责的范围和公开依据，模板使用者也能添加没有图片或演示的项目。

## 5. 问答来源与实际内容联动

- 修改 `src/lib/qa/public-sources.ts`，不再只读取 `projects[0]` 或写死 Kit 的项目路径。
- 按实际项目 slug 生成技术栈和关键决策来源，ID 使用 `project:<slug>:stack`、`project:<slug>:decisions`。
- 贡献来源读取贡献配置，以 URL 派生来源 ID；没有贡献时不再提供固定的空记录摘录。
- 项目、文章等页面关闭或相应内容移除后，相关来源不再参与问答；空白摘录也会被过滤。
- 保留两篇明确批准的文章摘录。新增 MDX、项目扩展字段和私人文件不会自动进入索引。

实际效果：问答引用与可访问页面更一致，替换项目后不会继续引用旧项目。当前仍是白名单检索与原文摘录，没有完成全量内容自动索引或逐项 AI 授权。

## 6. 内容维护、验证工具与文档

- 新增 `src/content/post-metadata.ts`，将文章元数据与 MDX 组件登记分开；页面与站点地图复用元数据。新增文章仍需显式登记本地 MDX。
- 新增 `src/components/contributions-view.tsx`，贡献页接入统一内容与模板仓库信息。
- 新增配置/组件和页面访问测试，调整问答与 API 测试；Vitest 支持 `.test.tsx`。
- Playwright 使用独立的 3100 端口、空 API Key 和独立限流目录，不复用正在运行的开发预览。
- 新增 `scripts/verify-fixtures.mjs`、`test:fixtures` 命令及 `run.ps1` 入口，用两套隔离示例配置检查替换资料后的实际 HTTP 行为。
- 截图脚本支持通过 `PREVIEW_URL` 指定服务地址。
- README 修正“没有远程仓库”的旧说明，并补充配置、路线及验证入口。
- 当前工作区还包含 `AGENTS.md` 的续做指引、`docs/ROADMAP.md`、配置迁移指南与 P0 验证文档；这些与本轮改动一起保留。
